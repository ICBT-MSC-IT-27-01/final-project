1. What the system contains

The system is deliberately split into three runnable projects. Each project has one responsibility, so the Angular user interface does not load or train the model directly.

ProjectFolderResponsibility
Angular frontendsrc/frontendDisplays forecasts, recommendations, history, Officer review and Administrator pages.
ASP.NET Core backendsrc/backend/AnuradhapuraAI.ApiProvides secure APIs, authentication, suitability logic, SQL persistence and orchestration.
Python forecasting servicesrc/forecasting-serviceLoads the saved LSTM v1 model and returns a seven-day weather forecast.

3. LSTM v1 to SQL to Angular workflow

  1. An Administrator requests an operational forecast.
  2. ASP.NET Core obtains the approved recent weather observations from Open-Meteo.
  3. The backend validates that exactly 30 daily observations are chronological and complete.
  4. The backend sends those observations to the Python POST /forecast endpoint.
  5. The Python service loads the saved v1 model and scaler, then returns exactly seven rainfall, temperature and humidity predictions.
  6. The backend validates the returned model version, dates and ranges, then stores a ForecastRun and seven ForecastRecord rows in SQL Server.
  7. Angular calls GET /api/forecasts/latest and displays the stored forecast.
  8. Angular calls the recommendation API; ASP.NET Core evaluates the approved crop rules against the stored seven-day forecast and returns factor-level explanations.

How to Run the Three Projects

Use three terminals. Keep each terminal open while testing.

4. Before you start

  • Use the project root: D:\My\MSc\Assignment\Final Project\Reports\app.
  • Start the backend before Angular.
  • Start the Python service before using Administrator operational forecast generation.
  • Do not run LSTM training commands. The commands below only load the existing trained model.

5. Run ASP.NET Core API — Visual Studio or terminal

Option A: Visual Studio

  1. Open src/backend/AnuradhapuraAI.slnx in Visual Studio.
  2. Set AnuradhapuraAI.Api as the startup project.
  3. Select the https launch profile.
  4. Press F5 or click the green Run button.
  5. Confirm the Output window shows the API listening at https://localhost:7055.

Option B: VS Code or terminal

cd "D:\My\MSc\Assignment\Final Project\Reports\app"
dotnet run --project .\src\backend\AnuradhapuraAI.Api\AnuradhapuraAI.Api.csproj --launch-profile https

Verify the backend in a browser:

https://localhost:7055/health
If the browser reports an untrusted local certificate, run dotnet dev-certs https --trust once, then restart the API.

6. Configure Angular to use the HTTPS API

Angular keeps API calls as /api/.... Its local proxy forwards them to the ASP.NET Core API. In src/frontend/proxy.conf.json, use:

{
  "/api": {
    "target": "https://localhost:7055",
    "secure": false,
    "changeOrigin": true
  }
}

secure: false is required only for the locally generated HTTPS development certificate. Restart Angular after saving this file.

7. Run Angular — VS Code terminal

cd "D:\My\MSc\Assignment\Final Project\Reports\app\src\frontend"
npm install
npm start

Open http://localhost:4200. The frontend proxies its API requests securely to https://localhost:7055/api/....

Run the Trained LSTM Model

8. Run Python FastAPI — VS Code terminal

cd "D:\My\MSc\Assignment\Final Project\Reports\app\src\forecasting-service"
python -m uvicorn forecasting_service.api:app --host 127.0.0.1 --port 8000

Verify that the trained model is loaded:

http://127.0.0.1:8000/health

The expected response contains "status": "Healthy" and "modelVersion": "v1".

No virtual environment? If the command reports a missing package, create one once: python -m venv .venv, activate it with .\.venv\Scripts\Activate.ps1, then run python -m pip install -e ..
