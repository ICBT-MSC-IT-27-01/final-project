# Phase 1 Architecture Proposal

## Current Repository State

The repository currently contains project guidance in `.agents/`, a contributor guide in `AGENTS.md`, and the initial skeleton created for Phase 1. It is not currently a Git repository.

## Final Project Structure

```text
src/
  backend/
    AnuradhapuraAI.slnx
    AnuradhapuraAI.Api/
    AnuradhapuraAI.Application/
    AnuradhapuraAI.Domain/
    AnuradhapuraAI.Infrastructure/
  frontend/
  forecasting-service/
tests/
docs/
.agents/
```

## Required Projects and Modules

- `AnuradhapuraAI.Api`: ASP.NET Core Web API presentation layer with controllers, request/response DTOs, validation, authorization, and API error handling.
- `AnuradhapuraAI.Application`: business/application layer for authentication, crop management, forecast orchestration, suitability scoring, recommendations, history, validation, and admin workflows.
- `AnuradhapuraAI.Domain`: core domain entities, value objects, constants, and business terminology shared by the application layer.
- `AnuradhapuraAI.Infrastructure`: SQL Server/EF Core persistence, external service clients, configuration-backed integrations, and infrastructure registrations.
- `frontend`: Angular application for public, registered-user, Agricultural Officer, and Administrator interfaces.
- `forecasting-service`: Python package with separate ingestion, preprocessing, training, evaluation, inference, and integration modules.

## Dependencies

Backend starts with the .NET SDK only. Phase 2 should add EF Core SQL Server packages when database work begins. Angular dependencies are declared in `src/frontend/package.json`; run `npm install` before frontend development. Python dependencies are intentionally empty except optional `pytest`; ML libraries should be added during the forecasting-service phase.

## Solution Format Decision

The backend solution will keep the current `.slnx` format generated by the installed .NET SDK. Do not convert it to classic `.sln` unless a concrete IDE, tooling, CI/CD, or compatibility issue is identified later.

## Environment Configuration

Backend configuration belongs in `appsettings.json`, user secrets, environment variables, or deployment-specific settings. The current placeholders cover SQL Server, approved feature flags, and the forecasting-service base URL. Python local settings are represented by `src/forecasting-service/.env.example`. Do not commit real secrets or private datasets.

## NPM Audit Note

The Phase 1 Angular install reports critical audit findings through `@angular/build` -> `piscina@5.2.0` (`GHSA-67c8-pqhq-4rmx`). This is development/build tooling, not application runtime code. The patched `piscina` line is `5.3.2`; the safest candidate remediation is to test an npm `overrides` entry for `piscina: 5.3.2` with Angular 21 before considering breaking Angular/tooling changes. Do not run `npm audit fix --force` without approval.
